# DSH 四态模式轮盘（DSH Mode Widget）

DeepSeek Harness（DSH）输入栏里的角色轮盘：**标准 BASE、计划 PLAN、审问 GRILL、限制 LIMIT**，把“直接做、先规划、先问清、简单答”放到一个按钮里。形成完整计划后，模式名位置会出现蓝色 **▶**，点击即可转入执行。

![DSH 四态模式轮盘展开效果](docs/images/轮盘.png)

标准 DSH bundle 插件，使用官方输入栏插槽。全部角色素材随包提供，无需额外账号、API Key 或付费服务。

> 第三方插件，非 DeepSeek 官方产品。**模式、规划轮次和执行资格均按会话独立。** 工具限制不是安全沙箱，仍需使用 DSH 自带权限与审批。

**当前发布候选：v0.2.0-rc.1。** 自动化与隔离浏览器回归通过；完整重启后的真实 DSH 端到端流程仍需验收，请按 Pre-release 分发。升级前保留原配置，升级后完整重启宿主，不能只刷新页面。

## 先分清：你用的是哪种 DSH

本仓库只有一套插件，不需要按角色或模式安装多个版本。

| 使用环境 | 安装入口 | 验证范围 |
|---|---|---|
| 官方桌面客户端（Electron） | 优先使用当前宿主的插件管理界面或内置 `plugin_manager` | 主要开发与验证目标：0.2.0-rc.2 |
| 浏览器中的 `dsh web` | 对应 Web profile 的 `dsh plugin --profile web …` | 沿用官方通用插槽接口；完整 Web 实机流程尚未验收 |

**不要把桌面端插件装到 Web profile。** 装进了不同的 profile，当前窗口就不会加载。

安装来源也尽量固定：GitHub、Release TGZ、本地开发目录是同一个包的不同来源。升级时先核对现有来源，不要为了更新盲目删依赖目录或锁文件。

## 特性

### 四种工作方式

| 模式 | 标签 | 用途 |
|---|---|---|
| 标准 | BASE | 不注入额外模式提示词，不增加本插件的工具限制，尽量保持原生 DSH 行为，同时也作为act模式使用，从plan/grill plan中的执行按钮中跳转过来时，可以执行它们的计划。 |
| 计划 | PLAN | 先只读了解现状、确认需求，再交付完整方案，等待你决定是否执行。用于制定执行计划、对齐用户需求 |
| 审问 | GRILL | 按决策依赖逐轮提问，把尚未确定的选择问清楚，再形成方案。在计划模式的基础上内置经典技能grill meskill，用于进行详尽的计划。 |
| 限制（bata）| LIMIT | 简短问答，限制文件修改、命令和子任务，避免把简单问题做复杂。用于限制DSH过度反应，阻止“雷霆大寻思”。在进行简单问答时使用，防止大肥鱼浪费你的token。（由于雷霆大寻思为偶发事件，难以稳定复现，目前针对此模式的测试仍然不足） |

PLAN 使用本插件的提示词与工具闸门，来贴合模式切换，所以**不是直接启用官方 plan-mode**。但我已经尽可以减少了修改。

### 轮盘与交互

- **输入栏内自然占位**：使用官方 `conversation.input.left` 插槽，不在 body 上悬浮、不追踪滚动坐标。
- **点击展开**：点头像或模式名，展开半圆角色轮盘；悬停时角色放大，点击选中并收起。
- **不动鼠标也有反馈**：点击展开的一刻初始化悬停高亮，无需先移动鼠标。
- **原地切回 BASE**：轮盘横向锚定头像中心，可见下沿与按钮下沿对齐；原地连续两次点击可选中 BASE。
- **右键偏好**：调整退出延迟、中文/英文标签及是否显示模式名。
- **收起方式**：Esc、点击外部，或移出后按设置的延迟收起；退出延迟设为 0 时不自动收起。
- **跟随宿主层叠关系**：不使用极高 z-index 或浏览器 top layer 抢占预览与遮罩。

### 计划 → 执行（核心）

执行按钮只代表**当前会话最新一份已完成的计划**，不是“这个会话以前写过计划”。

1. 切到 PLAN，提出任务、补充需求并讨论方案。
2. 模型只有在计划完整、没有待决需求时才调用 `mode_plan_ready`。
3. 该轮正常结束后，蓝色 **▶ 覆盖模式名**。讨论、澄清和草稿不会按字数自动点亮。
4. 同会话一旦排入新的真实任务或开始新轮次，旧执行资格立即失效，不必等新消息写入上下文。运行环境、技能目录、模型选择提示等说明不算追加需求。
5. 点击 ▶ 后，后端核对当前会话、归档/排队状态和一次性计划标识，仅将该会话切到 BASE 并发送“现在开始做吧”。交接成功后按钮收为头像；交接成功不等于任务已完成。
6. 处理中切模式只改变该会话的下一轮；本轮提示词和工具约束保持同一个固定模式。将鼠标放在头像上可查看“本轮模式 / 下一轮选择”。

**例如：A 已完成 → 你追加需求 → A 的 ▶ 消失 → 讨论 B 时不显示 → B 完整后才重新出现。**

- 不同会话的执行资格互不覆盖。
- 旧按钮、跨会话或重复点击不会执行另一份计划。
- 资格最多保留 10 分钟，不跨宿主重启持久化；执行失败不会自动恢复旧计划。
- 状态变化通过会话事件流推送；断线时先隐藏 ▶，连接恢复后重新确认。

## 安装

插件无需 `npm install`、构建步骤或额外运行时依赖。独立运行项目测试需要 Node.js 24 或更高版本。

> GitHub 安装示例以仓库和 `v0.2.0-rc.1` 标签已经发布为前提。若标签尚不存在，先使用本地完整资源包，不要把“标签未发布”当成插件故障。本项目尚未发布 npm，请勿直接按 npm 包名安装。

### 官方桌面端（Electron 客户端）请先看这一节

优先使用**当前桌面宿主内置的插件管理能力**。可以在桌面端会话里直接说：

```text
请使用当前桌面端内置的 plugin_manager 安装 dsh-mode-widget。
安装规格：github:MeteorNOX/dsh-mode-widget#v0.2.0-rc.1
先核对当前 profile、宿主版本，以及是否已有同名插件；已有安装时先报告来源与版本。
只使用工具实际支持的安装或更新操作。不要改装到 web profile，不要手改 desktop profile，
不要删除依赖目录或锁文件。若工具不可用，说明缺少的宿主能力。
完成后告诉我实际安装结果，以及是否需要完全退出并重开 DSH。
```

不同 DSH/CLI 版本对桌面 profile 的管理方式可能不同；不要把 `--profile desktop` 当成所有版本都能使用的通用命令。若宿主明确拒绝该操作，不能改用 Web profile 绕过。

首次安装或升级后如未显示按钮，**完全退出桌面客户端（包括托盘），再重新打开**。不要只看“安装成功”就认为当前窗口已加载新版。

### 方式 A：已有完整资源包或 Release TGZ（推荐）

- **Release TGZ**：下载 `dsh-mode-widget-0.2.0-rc.1.tgz`，保留压缩包，向桌面宿主提供它的**绝对路径**，使用内置管理工具支持的本地安装操作。
- **源码 ZIP**：先解压到稳定目录，进入包含 `package.json`、`cordis.patch.yml`、`lib/`、`assets/` 的那一层，再向宿主提供该目录的绝对路径。
- 不要混合两个解压目录；源码 ZIP 是项目文件，TGZ 是专用安装包。
- 若使用 `link:` 开发链接，安装后不要移动或删除源目录；普通包安装不等于开发链接。

### 方式 B：从 GitHub 安装指定版本

桌面端使用上面的内置管理工具提示，安装规格为：

```text
github:MeteorNOX/dsh-mode-widget#v0.2.0-rc.1
```

Web 用户可在自己的 Web profile 中执行：

```powershell
dsh plugin --profile web add github:MeteorNOX/dsh-mode-widget#v0.2.0-rc.1
```

该标签固定到一个版本，不等于跟随 `main` 分支的最新开发状态。

### 方式 C：本地开发安装（Web profile）

以下仅适用于 `dsh web`，不是桌面端的替代安装方法：

```powershell
dsh plugin --profile web add "link:C:/Plugins/dsh-mode-widget"
```

路径应指向**直接包含 package.json 的目录**。如果使用 Web CLI 安装 TGZ，也推荐绝对路径：

```powershell
dsh plugin --profile web add "C:/Downloads/dsh-mode-widget-0.2.0-rc.1.tgz"
```

安装完成后重启 `dsh web` 宿主，再刷新浏览器。Web 路径的完整实机兼容性尚未单独验收。

## 配置与运行时数据

不需要插件专用 API Key，不读取你的 DeepSeek 账户余额或其他模型账户凭据。

| 位置 | 用途 |
|---|---|
| `$DSH_HOME/dsh-mode-widget/state.json` | V2 默认模式、个人偏好与每个会话独立的模式 |
| `$DSH_HOME/dsh-mode-widget/state.json.v1.bak` | 首次保存 V2 时保留的 V1 原始配置备份 |
| `$DSH_HOME/dsh-mode-widget/requests.log` | 仅设置 `DSH_MODE_DEBUG=1` 时写入的排查日志 |
| 宿主内存 | 执行资格、轮次及一次性标识，重启后清空 |

未设置 `DSH_HOME` 时，使用用户主目录下的 `.dsh`。素材全部包含在包内，`DSH_MODE_ASSETS` 仅是可选开发覆盖目录。

`mode_config` 只修改默认模式和全局偏好，不改变已有会话。默认模式仅在首次建立会话模式时使用；会话卸载、归档后模式仍保留。隐藏标签请使用偏好中的“模式名”开关。

### v0.2.0-rc.1 状态核心迁移

- 必须完整重启 DSH 宿主；前端和后端协议不一致时暂停操作并提示重启，避免继续使用旧的全局模式接口。
- V1 中真正生效的是 `defaultMode`，旧 `sessions` 映射此前被忽略，可能已经过期。V2 保留默认值和偏好，但不复活这些旧映射；每个会话首次接入时从保留的默认值初始化，随后独立保存。
- 第一次 V2 保存前创建不覆盖已有文件的 V1 原始备份。状态无法读取或保存时明确失败，不悄悄退回标准模式或假装保存成功。
- 宿主重启会清除计划执行资格，不从历史记录自动重新点亮旧 ▶；会话模式则从 V2 配置恢复。
- `/dsh-mode/diag` 的 `runtime` 显示实际加载的 `coreBuild`、`protocolVersion`、状态版本与启动时间；带 `?session=…` 可核对该会话状态，不再靠文件修改时间猜测运行版本。

## 安全边界（请务必一读）

- **会话模式，会话级执行**：在 A 会话切模式或执行，不改变 B；提示词和工具闸门统一使用本轮固定模式。
- **工具闸门不是 OS 沙箱**：判断依赖工具名与保守命令语法，Office、浏览器或其他插件工具不保证全面覆盖。不要因此降低 DSH 的权限与审批设置。
- PLAN 仅放行简单只读 shell 形式，如 `pwd`、`ls lib`、`git status --short`。复杂读取请用宿主 read/glob/grep；换行串联、重定向、删除分支、`find -delete` 等不允许。
- 修改接口要求 JSON，拒绝非可信页面 Origin，不开放通配跨域读取；这不替代宿主身份认证。不要把插件接口单独暴露到公网。
- 不改写宿主 fetch/WebSocket，不抓取其他会话 DOM，不通过 React 内部对象猜测会话。
- 本插件不负责修复其他 HTML 渲染插件，也不会擅自改写模型输出的 HTML。
- 反馈问题时请勿上传密钥、完整个人配置、未脱敏日志或其他会话内容。

1. 输入栏能看到角色胶囊，点击可展开并选择模式。
2. 图片预览、模态遮罩出现时，不会有按钮穿到它们上面。

## 常见问题

**装完没有按钮？**

先确认 profile 是否与当前 DSH 窗口一致，安装的是不是包含全部素材的完整包，以及宿主是否需要重开。桌面端安装到 Web profile 不会生效；自定义客户端声明或后端更新后，仅刷新页面可能不够。

**为什么在一个会话切到 PLAN，另一个也变了？**

状态核心 V2 不再有这个行为。若仍出现，先查看 `/dsh-mode/diag` 是否实际加载 `session-core-v2-20261028`；不要仅凭磁盘文件已更新就认定宿主已更新。

**为什么已经写了一段方案，还没有 ▶？**

不会按回复长度判断完成。模型必须显式提交完整计划，且该轮正常结束、没有被新需求打断。资格还会因超时、重启或新轮次失效；连接中断时也会先隐藏。

**PLAN 导致 HTML 渲染失败吗？**

模式插件不接管 HTML 渲染。应先检查输出 HTML 和对应渲染插件，不能仅凭某次 PLAN 输出失败就认定是模式闸门造成的。

**为什么不能直接执行某条“看起来只读”的命令？**

命令允许列表刻意保守，复杂参数可能被拒绝；请改用读取工具，或完成规划后由用户切到 BASE。不要通过拼接命令绕过限制。

**要额外配置密钥、装依赖或打开所有构建脚本吗？**

不需要插件专用密钥，也没有安装/编译脚本。若安装器报错，按具体宿主和具体依赖排查，不要为此开放所有依赖的构建脚本。
