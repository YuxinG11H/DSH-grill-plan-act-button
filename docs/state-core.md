# 会话状态核心 V2

本次范围：只调整模式、会话、轮次和执行交接；不调整轮盘 CSS、角色图、布局、动画或官方插槽位置。

## 状态归属

- `state.mjs`：V2 持久化默认值、全局偏好、每个会话的选中模式。读写失败抛出明确错误，不回退成更宽松模式。
- `session-core.mjs`：唯一运行时状态机。每个会话拥有选中模式、本轮固定模式、计划资格、输入去重、读取预算及执行相关性。
- `index.js`：官方事件、工具、提示词与 HTTP/SSE 的适配层，不另存模式或“最近计划”。
- `plan-availability.mjs`：旧类名兼容导出，指向同一个核心，不再维护另一套状态。
- 客户端：显示宿主给出的状态。只有得到当前协议 V3 响应后才允许修改模式/执行；不乐观伪装已经切换成功。

## 模式一致性

会话第一次接入时从默认值初始化，之后独立保存。处理中切换只改变下一轮的选中模式；本轮提示词、工具限制、读取预算和计划提交共享固定模式。客户端沿用原 UI，通过头像提示文字说明下一轮选择。

`session/disposed` 是运行时卸载，不是删除会话。它清除计划、输入及执行的临时资格，但不删除持久化模式。归档/取消归档也不删除模式。宿主重启后模式恢复，执行资格不会恢复。

如果插件在已经进行的轮次中途加载，核心通过已安装版本的 `session.snapshotEvents()` 检测此情况，采用限制性状态并拒绝完成标记；等待下一轮，不假造历史模式或自动恢复旧按钮。

## 任务输入与上下文

使用官方 `agent/inbox/inserted` / `claimed` / `discarded`，以及持久化 `agent/inbox/spliced` 和 `user/message`。按消息 ID 去重：入队、认领和写入对话不会被误认为三次新需求。

- 新的真实任务入队时即撤销旧资格，不必等它进入模型上下文。
- `user`、父级/钩子任务和 `plugin:*` 自动化任务按任务输入处理。
- 已明确标记为 `runtime-context`、`skill-catalog`、`model-selection`、`ptc-mode` 等上下文的消息不按新任务处理。其他具名上下文默认不当成人类请求；未标记的旧消息保守视为任务。
- 初始的一批输入允许共同构成一轮任务；开始工作/提交计划后的新输入永久替代该轮计划。
- 取消排队输入会清除排队记录，但不会复活被它撤销的旧计划。取消尚未认领的执行请求解除交接锁，并仅在没有后续模式变更时回滚自身模式修改。

## 执行交接

状态路径：`完整计划提交 → 同轮正常完成 → ready → dispatching → queued → running → completed/failed`。

- 提交资格绑定会话、轮次和随机 token，只能在该会话相应规划轮次提交。
- 执行前校验目标、归档祖先、待处理任务、token、TTL 与开关。无目标会话或有新任务时不能猜测兜底。
- 一次性消费资格，先成功保存该会话的标准模式，再调用 `followup`。保存失败不发送执行消息。
- 执行消息具备完整 ID 和 `plugin:dsh-mode-widget` 来源，交接相关性在发送前安装；认领后绑定真实执行轮次。
- 失败只回滚该交接自身尚未被用户更新的模式写入，不覆盖后来选择，不恢复已消费 token。
- 发送后报错但已确认入队/认领的情况视为“已接受但通道报错”，不重复发送。
- 此处不是跨文件和宿主队列的数据库事务，不承诺任务完成或宿主崩溃下的 exactly-once；保证插件不会因重复点击重复交接同一资格，并在不确定状态保守拒绝。

## 状态协议与运行版本

`protocolVersion=3`，运行 build 为 `session-core-v3-planning-manual`，持久化 schema 仍为 V2。模式、计划资格、失败原因共享同一个 `planEpoch` / `planRevision`，客户端先校验版本和顺序再更新全部状态。

有序 SSE 是宿主 epoch 的权威来源；迟到的、此前没见过的旧 HTTP epoch 不能覆盖新 SSE。没有流时 HTTP 请求序列也防止跨 epoch 倒退。同一 epoch 内以宿主 revision 排序。旧执行请求的网络错误不得清掉新计划。

`GET /dsh-mode/diag` 返回实际运行的 build、协议、持久化版本和启动时间。磁盘文件更新、客户端 HMR、宿主重载是不同事情；本次升级必须完整重启宿主后再核对。

## V3：手动继续与提问策略

`POST /dsh-mode/state` 的 `attachView:true` 为会话登记当前页面 `viewId`；新页面实例会撤销旧手动资格。来自轮盘的显式切换使用 `manualTransition:true`，只有 PLAN／GRILL → BASE 成功切换才授予 `manualToken`。处理中仍保持固定轮次模式，结束后才能使用手动资格；新轮次会清除它。普通执行交接内部切换不调用这条授权路径。

手动资格独立于 `planToken`，仅在当前页面、当前会话处于空闲标准模式且无排队任务时有效。`POST /dsh-mode/execute-manual` 核对 `manualToken` 和 `viewId` 后一次性消费，再复用现有交接与审批边界。不能将手动标识交给正常计划执行接口。两条路径都发送“现在请直接执行任务。”，均不自动重发，不在失败后恢复资格。

偏好字段 `disablePlanQuestionCard=true`、`disableGrillQuestionCard=false` 接受布尔值。提示词生成时捕获策略，工具闸门沿用对应请求策略；中途改配置不改变已发送给模型的请求，下一请求采用新值。禁用时阻止 `ask_user_question`，要求改用必要的编号文字提问。标准模式提示词仍为空。

无标记的正常规划轮次以 `PLAN_NOT_SUBMITTED` 解释未点亮的原因，不自动猜测计划完成。普通状态使用原生 title／无视觉浮层的辅助说明；只有手动按钮保留风险提醒浮层。

## V1 迁移

V1 的实际函数忽略会话映射，只使用 `defaultMode`。因此 V2 保留默认值和偏好，但不恢复可能过期的 V1 `sessions`；第一次 V2 保存前把原始文件备份到 `state.json.v1.bak`，不覆盖已有备份。V2 每个会话接入时保存独立模式，改默认值不追溯已有会话。

迁移是幂等的，读取旧文件本身不覆盖文件；执行资格不持久化。损坏或未知状态版本明确报错而不是覆盖原配置。

## 自动化覆盖

运行 `node scripts/verify.mjs`。包含真实安装版 SlotCore 的 list 插槽检查、旧生命周期回归、会话核心测试、真实 HTTP/SSE/官方事件适配测试、实际客户端 reducer/动作的乱序测试和发布安全检查。全部持久化测试使用项目内临时目录或内存存储，不操作真实用户状态。

隔离浏览器夹具 `node scripts/test-slot-server.mjs` 使用真实宿主适配和内存核心，验证轮盘交互、切换会话、计划更新、滚动和遮罩。它使用最小 React 生命周期适配器，不代替重启后真实 DSH 的最终验收。
